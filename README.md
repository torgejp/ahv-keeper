# AutoHedge keeper(自動rebalance + 異常通知)

**v7 対応版。** 10分おきにvaultを確認し、①ヘッジが目標からずれていたら `rebalance()`、②ヘッジ口座の証拠金が帯(名目の22〜38%)から外れていたら `settle()` を送信、③異常があればスマホへ通知します。`VAULT`(v7のアドレス)の指定が必須です。

## 仕組み
- `rebalance()` と `settle()` は**誰でも呼べる**関数で、資金を動かす権限はありません。keeper用の鍵が漏れても、失うのはガス代(HYPE)だけです。
- 鍵を設定しなければ「監視+通知のみ」で動きます(rebalanceは手動)。

## セットアップ(約10分)
1. **ntfy**(無料)をスマホに入れ、推測されにくいトピック名(例 `ahv-xxxxxxxx`)を購読する。
2. **keeper用の新しいウォレット**を作る(Rabby等で新規アカウント)。HyperEVMへ HYPE を 0.1 ほど送る(1回のrebalanceは約0.0002 HYPE程度)。秘密鍵を控える。※本番ウォレットの鍵は使わない。
3. GitHubに**非公開リポジトリ**を作り、このフォルダの中身(`keeper.mjs` `package.json` `.github/workflows/keeper.yml`)を置く。
4. リポジトリの Settings → Secrets and variables → Actions に登録:
   - `NTFY_TOPIC` = 手順1のトピック名
   - `KEEPER_PK` = 手順2の秘密鍵(0x…)
5. Actions タブ → `AutoHedge keeper` → Run workflow で試運転。ログに vault の状態が出て、スマホに「稼働中」通知が来ればOK。

## 通知の種類
| 通知 | 条件 | 対応 |
|---|---|---|
| 清算が近づいています(緊急) | 清算価格まで +15% 未満 | 証拠金を追加 |
| 清算価格が近め | +25% 未満 | 証拠金追加を検討 |
| 証拠金が薄い | レバレッジ 5倍超 | keeperが settle() で補充(失敗が続くなら手動) |
| settleできません / 必要です | settle() が帯の外で失敗、または鍵未設定 | ログを確認。放置すると清算の恐れ |
| rebalanceできません / ヘッジがずれ | rebalance失敗・目標から20%超ずれ | ログを確認 |
| keeperのガス不足 | keeperのHYPEが0.01未満 | HYPEを送る |
| データを取得できません | RPC/APIが応答しない | 一時的なら放置 |
| 稼働中(1日1回) | — | 止まっていないかの確認用 |

同じ通知は一定時間(1〜24時間)は再送しません。

## 注意
- GitHub Actions の定期実行は数分遅れたり、まれに抜けたりします。価格の急変では間に合わないことがあります。
- 証拠金の補充・回収は `settle()` が自動で行います(LPの一部解除や、HyperCoreの利益のEVMへの戻しを含む)。keeperが止まると証拠金不足で清算されたり、利益が溜まって出金が待たされることがあります。
- 未監査・自己責任です。
